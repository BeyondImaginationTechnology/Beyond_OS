# Jaguar monthly usage limits

Jaguar's model-backed Explain/Build chat has a monthly allowance of five completed model requests and a 0.10 BIT$ ceiling per identity. A signed-in identity is its Beyond ID user ID, so the allowance follows the account across devices. A guest identity is a one-way HMAC of the server-observed client IP using a dedicated random key stored in private server storage; the raw IP is not written to the Jaguar usage ledger. Guest usage fails closed if the private key or IP is unavailable. Guests and signed-in accounts use the same allowance. Free PHP fast-lane replies do not consume model requests or BIT$ allowance.

Forwarded client IPs are accepted only when `REMOTE_ADDR` falls within an explicitly configured trusted-proxy CIDR. Configure `BEYOND_TRUSTED_PROXY_CIDRS` as a comma-separated list in protected server configuration, or `security.trusted_proxy_cidrs` in `config/live.php`, using the hosting provider's current proxy ranges. Only `CF-Connecting-IP` is read from a trusted peer; `X-Real-IP` and `X-Forwarded-For` are ignored. An empty list ignores all forwarded headers and uses the direct peer address, which can make guests behind a shared proxy share one allowance. Restrict the origin so requests cannot bypass the trusted proxy, and keep the provider's proxy ranges current. Never configure `0.0.0.0/0` or `::/0` as trusted.

The Modal runtime reports prompt and generated token counts internally, plus synchronized elapsed GPU inference time around `model.generate`. The public interface shows completed model requests and remaining BIT$ only; token counts are not exposed to users. Jaguar estimates BIT$ at Modal's current L4 GPU rate of 0.000222 BIT$ per GPU-second, using the stated 1:1 BIT$/Modal-credit mapping. This is a GPU-only estimate: container startup, scaledown, CPU, memory, and shared container overhead are not attributed to a visitor. The per-identity BIT$ threshold is checked before model calls against prior estimated use; it cannot guarantee actual per-user Modal spend because the provider bills shared container resources. Modal's workspace Usage & Billing page remains authoritative for actual credit consumption, and the workspace budget is left unchanged.

The five-request monthly limit is an additional hard guard so account/IP switching cannot turn a small per-user allowance into unlimited GPU calls. A successful Draw image also consumes one of these requests. Failed or unavailable runtime calls release their reservation; a completed response without valid metering counts as a request. Abandoned model-request reservations expire after five minutes; text runtime calls have a 105-second deadline and Draw has a 180-second worker deadline. The database period is UTC calendar month. The workspace's own Modal usage budget and spend limit are independent and are not changed by this feature. Signed-in wallet balance is read from the Beyond ID BITS wallet. Draw requires sign-in and 10 BIT$ in the wallet. Before calling `JAGUAR_DRAW_RUNTIME_URL`, it atomically reserves both one monthly GPU request and 10 BIT$ in `jaguar_draw_holds` so concurrent requests cannot overspend. The Draw worker returns measured GPU seconds; after a valid image response the API records that usage and one idempotent wallet debit. Failed generations release both reservations without a debit. Holds abandoned by a crashed request are recovered when that user's Jaguar balance is next read, after ten minutes. Missing workers and insufficient balances never start a hold.

Deployment order matters: configure the trusted-proxy ranges and restrict direct origin access, deploy the runtime response with token and GPU-time metadata, and apply the `20260929_01_jaguar_draw_holds` database migration before deploying the updated PHP Draw path. The PHP API fails closed when the model runtime does not return bounded usage metadata, because it cannot safely offer unmetered model calls.
